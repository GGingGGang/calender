# calender

Windows 11용 반투명 바탕화면 일정 위젯입니다. WebView2 Evergreen Runtime과 Git for Windows(Git Credential Manager 포함)가 필요합니다.

## 시작하기

1. `calender.exe`를 실행합니다. 헤더로 위젯을 옮기고 가장자리로 크기를 조절합니다.
2. **설정**에서 기존 GitHub 비공개 저장소의 HTTPS 주소를 입력합니다. 해당 저장소에 쓰기 권한이 있는 계정으로 Git Credential Manager에 로그인합니다. 빈 저장소도 연결할 수 있습니다.
3. Daily의 **Todo ＋** 또는 설정의 **일정 추가**를 사용합니다. Daily 카드를 열어 진행 상태를 선택하거나, 카드를 드래그해 상태와 순서를 바꿀 수 있습니다. 반복 일정의 진행 상태는 **이 날짜만**에서 변경합니다. Weekly와 Monthly에서는 날짜를 클릭해 Daily를 엽니다.
4. 두 번째 Windows 기기에서도 같은 실행 파일을 열고 같은 저장소에 연결합니다.

위젯에 포커스가 있을 때 **← / →**로 이전·다음 기간을 봅니다. Daily는 하루, Weekly는 한 주, Monthly는 한 달씩 이동합니다. 편집창과 입력 필드에서는 방향키로 입력 내용을 조작할 수 있습니다.

**Tab**은 Daily → Weekly → Monthly → Daily 순서로 보기를 전환하고, **Shift+Tab**은 역순으로 전환합니다. 편집창과 설정 창에서는 Tab으로 입력칸과 버튼을 이동합니다.

위젯의 버튼과 카드를 Tab으로 탐색하려면 **F6**을 누릅니다. 다시 F6을 누르면 보기 전환으로 돌아갑니다. Daily 카드에서 **Alt+↑ / Alt+↓**로 같은 상태 열 안에서 한 칸씩 정렬하고, Enter로 편집창을 엽니다.

일정 편집창의 메모에는 여러 줄을 입력할 수 있습니다. Daily 카드에는 두 줄까지 미리 표시하며, 전체 내용은 편집창에서 읽습니다. 반복 일정은 공통 메모와 날짜별 메모를 함께 보관합니다. **이 날짜만**에서 작성하면 다른 회차의 메모에는 영향을 주지 않습니다.

반복 일정은 생성하거나 **반복 전체**를 편집할 때 Weekly와 Monthly 표시 여부를 각각 선택합니다. 기본값은 양쪽 모두 표시입니다. 완료한 일정은 Daily의 Done 열과 Weekly·Monthly 달력에 반투명한 회색과 취소선으로 표시됩니다. 반복 일정은 완료한 날짜의 회차에만 적용됩니다.

Weekly와 Monthly에서 같은 일정이 연이어 있는 날짜는 같은 줄에 이어집니다. Monthly에서는 주마다 막대를 나누고 이름을 가운데 한 번 표시합니다. 일정이 많은 주는 모든 막대가 보이도록 높이가 늘어나며, 위젯 안에서 세로로 스크롤할 수 있습니다. 건너뛴 날짜는 비워 두며, 날짜나 막대를 클릭하면 해당 날짜의 Daily가 열립니다.

**설정 → 그룹 → 그룹 추가**에서 이름과 색상을 정하고, 일정 편집창에서 소속 그룹을 선택합니다. 반복 일정은 **반복 전체**에서 그룹을 변경합니다. 위젯 상단의 그룹 필터는 Daily·Weekly·Monthly에 함께 적용됩니다. 기존 일정은 미분류로 표시하며, 그룹을 삭제하면 소속 일정과 메모는 미분류로 남습니다. 그룹 정의는 같은 GitHub 저장소의 `calender/groups/`에 동기화됩니다.

설정의 일정 검색창에서 제목, 메모, 그룹 이름으로 일정을 찾을 수 있습니다. 반복 일정의 날짜별 제목이나 메모가 일치하면 해당 날짜가 결과에 표시됩니다. 날짜가 붙은 결과를 열면 그 회차의 **이 날짜만** 편집으로 이동합니다. 검색어를 지우면 전체 목록이 다시 표시됩니다.

## 데이터와 동기화

일정 파일은 저장소의 `calender/events/`에 보관합니다. 기기별 창 위치, 마지막 조회 결과, 재전송 대기 데이터, 작업 복사본은 `%APPDATA%\calender`에 저장합니다. 앱은 저장소 기본 브랜치에 직접 push하므로 해당 계정에 직접 push 권한이 필요합니다.

최초 동기화 후 일정 변경은 즉시 로컬에 저장됩니다. 앱이 실행 중이면 마지막 동기화 시도에서 10분이 지났을 때, 또는 저장이 10건 쌓였을 때 먼저 도달한 조건으로 동기화합니다. 먼저 pull한 뒤 대기 중인 변경을 한 커밋으로 묶어 push합니다. 카드 한 번 이동은 여러 카드의 순서가 바뀌어도 1건입니다. 실제 차이가 없으면 커밋을 만들지 않습니다.

하단에 전송 대기 건수가 표시됩니다. **동기화**를 누르면 즉시 보낼 수 있습니다. 앱을 닫아도 대기 목록은 보존됩니다. 전송 실패 시 다음 주기에 재시도합니다. **충돌 해결**에서는 제목·메모 등 항목별로 이 기기 값과 저장소 값 중 하나를 골라 **선택 적용**할 수 있습니다. 한쪽 값을 모두 적용하는 것도 가능합니다.

Weekly와 Monthly는 일요일에 시작합니다. 모든 화면에서 일요일과 공휴일 날짜는 빨간색, 그 외 토요일 날짜는 파란색으로 표시합니다. 내장된 대한민국 공휴일은 2026년과 2027년이며, 우주항공청의 [2026년 월력요항](https://www.kasa.go.kr/prog/bbsArticle/BBSMSTR_000000000010/view.do?bbsId=BBSMSTR_000000000010&nttId=B000000001860Pe2zT3)과 [2027년 월력요항](https://www.kasa.go.kr/bbs/BBSMSTR_000000000018/view.do?nttId=B000000003234Li6nD2)을 기준으로 합니다.

## 빌드 및 테스트

Windows에서 Go 1.25, Node.js, npm, Git을 사용합니다.

```powershell
npm.cmd install
npm.cmd run build
go test ./...
```

TypeScript 화면은 빌드 시 실행 파일에 포함됩니다. Go의 날짜 계산과 Git 동기화는 바탕화면 창과 설정 창이 함께 사용합니다. 테스트는 임시 로컬 Git 저장소 두 곳에서 독립 변경 병합, 충돌 선택, 오프라인 읽기, 전송 실패 후 복구, 삭제 동기화와 날짜 경계를 확인합니다.

Windows에서 위젯과 설정 창이 실행되고 WebView2에서 호출한 동기화 결과가 기록되는 것을 확인했습니다. Win+D 후 표시, 한글 입력, 카드 드래그, 위젯 밖의 아이콘 클릭과 Explorer 재시작 후 복구는 수동 확인 항목입니다. Git 동기화 자동 테스트는 로컬 저장소를 사용합니다.
